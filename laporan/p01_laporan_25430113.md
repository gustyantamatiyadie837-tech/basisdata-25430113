## 4. Jawaban Titik Analisis
**Titik Analisis 1**
- **Konsekuensi pencarian galat di internet:** Jangan cuma pakai kata kunci "MySQL", karena solusinya kadang tidak pas. MariaDB punya beberapa fungsi, sintaks, dan storage engine yang berbeda.
- **Kapan dokumentasi MySQL relevan:** Saat mengolah query standar SQL dan fitur umum basis data relasional.
- **Kapan harus merujuk dokumentasi MariaDB:** kalau masalahnya soal performa di versi MariaDB terbaru, pengaturan file my.ini, storage engine khas MariaDB (seperti Aria atau ColumnStore), atau galat yang memang khusus MariaDB.

 **Titik Analisis 2**
[Galat Akses Ditolak]**(img/d3_analisis2_25430113.png)**
Keterangan : Perbandingan pesan `ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO)` dengan Gambar 1.10:
- **ERROR 1045 (28000)**: Kode galat autentikasi dan kelas otorisasi SQLSTATE.
- **'root'@'localhost'**: Akun pengguna dan host asal koneksi.
- **(using password: NO)**: Klien masuk tanpa mengirimkan kata sandi.
**Kesimpulan:** Akun `root` telah diamankan. Perbaikannya yaitu masuk pakai `mysql -u root -p`.

**Titik Analisis 3**
Keterangan : information_schema tetap kelihatan oleh mhs_113 karena isinya cuma metadata.Sebaliknya, akses ke basis data mysql ditolak dengan ERROR 1044, karena di dalamnya ada tabel kredensial dan hak akses seluruh pengguna server, sedangkan mhs_113 ga punya izin untuk membukanya.
 **Perbedaan Kode Galat 1044 dan 1045:**
- **ERROR 1044 (Access denied for user to database):**pengguna berhasil/layak masuk server, tetapi pengguna tidak memiliki izin (*grant*).
- **ERROR 1045 (Access denied for user using password):**Pengguna gagal masuk ke server MariaDB karena nama pengguna atau kata sandi yang dimasukkan salah/tidak sesuai.


**Titik Analisis 4**
Keterangan : Mode `cookie` lebih aman daripada mode `config` karena: **Keamanan Kredensial** dan **Autentikasi Dinamis**

## 7. Pembahasan dan Kendala
### Kendala yang Dihadapi dan Solusi
**Masalah Service MySQL Berhenti Mendadak (*Shutdown Unexpectedly*)**
![Kendala MySQL Shutdown Unexpectedly]**(img/d1_erorxampp_25430113.png)**
- **Kendala:** Layanan MySQL pada XAMPP Control Panel gagal berjalan (*Start*) dan terus mengalami crash dengan pesan galat `Error: MySQL shutdown unexpectedly`.
- **Penyebab:** Terjadi kerusakan file (*corrupted data/log*) pada direktori penyimpanan tabel MariaDB yang menyebabkan servis MySQL tidak dapat membaca file inisialisasi dengan benar.
- **Penyelesaian:** Melakukan pemulihan folder data MySQL dengan langkah-langkah berikut:
  1. Mengubah nama folder `xampp/mysql/data` menjadi `xampp/mysql/data_old`.
  2. Duplikasi folder `xampp/mysql/backup` dan ubah namanya menjadi folder `data` baru.
  3. Memindahkan seluruh folder basis data bawaan serta file `ibdata1` dari folder lama ke folder `data` baru.
  4. Menjalankan kembali tombol **Start** MySQL pada XAMPP Control Panel hingga servis berjalan normal.
